# annie-decide：Annie Duke 决策流程

下文的 `<决策目录>` 指同目录 `config.local.json` 里的 `decisionDir`（不进仓库，格式见 `config.example.json`），开始前先读出来。

体系的内容以这份学习文档为准：`<决策目录>/Annie Duke 决策体系.md`。开始前先读它；文档和本 skill 冲突时，以文档为准，并提醒用户本 skill 需要同步。

## 文件位置

| 用途 | 路径 |
|---|---|
| 决策记录（一次决策一个文件） | `<决策目录>/记录/YYYY-MM-DD 标题.md` |
| 知识追踪表（复盘后追加一行） | `<决策目录>/知识追踪.md` |
| 复盘提醒 | 滴答「🤖AI Tasks」的「⏳ 等条件」，用 `dida-tasks` skill 的脚本建 |

## 三种用法

| 用户说的 | 做什么 |
|---|---|
| `/annie-decide <要决定的事>` | 新决策，走下面的「新决策流程」 |
| `/annie-decide 复盘 <标题或关键词>` | 复盘一条已有记录，走「复盘流程」 |
| `/annie-decide 列表` | 列出 `记录/` 里所有决策：标题、日期、复盘日、是否已复盘 |

## 交互原则

- **一次只推进一步，问完等用户回答**，不要一口气把所有问题抛出来
- **决定由用户做。** AI 可以补充用户没想到的结果、提供外部视角的基础概率、指出前后矛盾，但不替用户选；AI 的补充在记录里标〔AI〕
- 概率一律用百分比。用户说「可能」「大概率」时，追问一个数字
- 用户说「这事不值得这么麻烦」时，尊重，直接跳到快速决定
- 用中文，句子短

## 新决策流程

### 第 0 步：搞清楚在决定什么

用一两句话复述：要决定的是什么、有哪些选项、什么时候必须决定。选项少于两个时，帮用户想想有没有被忽略的选项（包括「不做」和「推迟」）。

### 第 1 步：值不值得多想

依次用这几个工具判断，任何一个给出「不值得」就进入**快速决定**：

1. **快乐测试**：这个决定的结果，一年后还会影响你的快乐吗？
2. **重复的选择**：这类决定会经常出现吗？
3. **免费的尝试**：下行风险很小、上行空间很大吗？
4. **只剩一个选项测试**：如果只能选其中任何一个，你都能接受吗？
5. **可逆性**：选错了能不能退、退的代价多大？

**快速决定**：告诉用户为什么不值得多想，请用户直接选一个（或用拆分决定先做个低成本的小尝试），在回复里写一句结论。快速决定**不写记录文件、不建提醒**，到此结束。

值得多想的，进入第 2 步。

### 第 2 步：六步分析

对每个选项依次做：

1. **列出可能结果**：请用户先列，AI 再补充遗漏的（标〔AI〕）。一般 3–5 个结果，好的坏的都要有
2. **标出偏好**：每个结果对用户来说是很好、好、一般、差还是很差
3. **估计概率**：先给外部视角，同类事情一般的基础概率是多少（AI 能查到可靠来源就附上来源，查不到就说明是估计）；再请用户根据自己的情况调整，得到每个结果的百分比。概率合计应接近 100%
4. **综合判断**：算出喜欢的结果合计多少、不喜欢的合计多少；问用户最坏情况能不能承受

所有选项做完后，用表格并排比较，请用户做出选择，并说出理由。

### 第 3 步：事前验尸

1. 假设已经过了一段时间，这个决定的结果很糟。最可能是什么原因？请用户列 2–3 个
2. 把原因分成「自己能控制的」和「控制不了的」
3. 能控制的：想一个预防办法
4. 控制不了的：想好发生时怎么应对
5. 可选：事后回溯，假设结果很好，是什么促成的，怎么让它更可能发生

### 第 4 步：预先承诺

问用户要不要设：

- **触发条件**：出现什么信号就必须重新评估（比如亏损到某个数、某个日期前没进展）
- **自动执行的约束**：比如条件单、提前约好的截止日期

没有也可以，写「无」。

### 第 5 步：定复盘日并记录

1. 和用户商量复盘日：结果大致能看出来的时候
2. 按下面的「记录模板」写决策记录文件。文件名 `YYYY-MM-DD 标题.md`，日期用决策当天
3. 用 dida-tasks 脚本建复盘提醒：

```bash
node ~/.claude/skills/dida-tasks/scripts/aitasks.mjs add "复盘决策：<标题>" --col waiting --tags <领域> --due '<复盘日> 10:00' --remind --content "记录在 <决策目录>/记录/<文件名>。到期运行 /annie-decide 复盘 <标题>"
```

领域标签从 `工作` `摄影` `健康` `学习` `生活` `投资` 里选一个。

4. 回复用户：选了什么、记录文件路径、复盘日

## 复盘流程

1. 在 `记录/` 里找到对应文件，读出当时的选择、各结果的概率、事前验尸和触发条件
2. 问用户实际结果是什么
3. 对照四象限判断：

| | 结果好 | 结果坏 |
|---|---|---|
| **决策好** | 应得的回报 | 运气不好 |
| **决策差** | 侥幸 | 罪有应得 |

4. 依次问：
   - 当时知道什么、不知道什么？
   - 有没有当时能查到、但没去查的信息？
   - 当时估的概率准不准？实际结果落在哪个预测里？
   - 事前验尸里想到的原因发生了吗？有没有没想到的？
   - 下次同类决定，要改什么？
5. **只从决策质量里学，不从运气里学。** 用户把运气不好归咎于自己、或把侥幸当成本事时，指出来
6. 把复盘写进记录文件的「复盘」一节，并在知识追踪表追加一行
7. 把滴答里对应的「复盘决策：<标题>」标完成：

```bash
node ~/.claude/skills/dida-tasks/scripts/aitasks.mjs done "复盘决策：<标题>" --note "<一句话结论>"
```

## 边界

- 记录文件只写在 `<决策目录>/记录/`；滴答只写「🤖AI Tasks」，规则见 `dida-tasks` skill
- 涉及隐私的决定（关系、健康等），记录里只写必要的信息；用户要求不留记录时，只在对话里走流程，不写文件也不建提醒
