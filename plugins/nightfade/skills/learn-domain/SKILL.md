# learn-domain：从零学一个新领域

下文的 `<学习根目录>` 指同目录 `config.local.json` 里的 `learnRoot`（不进仓库，格式见 `config.example.json`），开始前先读出来。

方法的内容以同目录的 `method.md` 为准。开始前先读它；文档和本 skill 冲突时，以文档为准，并提醒用户本 skill 需要同步。

## 三种用法

| 用户说的 | 做什么 |
|---|---|
| `/learn-domain <领域>`、「我想学 X」 | 在 `<学习根目录>` 里找不到这个领域的计划时，走「新领域」 |
| `/learn-domain 学 <领域>`、「今天学 X」 | 读计划，走「学一次」 |
| `/learn-domain 检查点 <领域>`、「X 学到哪了」 | 读计划，走「检查点」 |

找计划：在 `<学习根目录>` 下搜 frontmatter 含 `type: learning-plan` 的文件，按标题里的领域名匹配，名字有出入（宏观 / 宏观经济学）时列出候选请用户确认。

- 用户说「我想学 X」而计划已存在：告诉用户，问是接着学还是重新规划
- 用户说「今天学 X」而计划不存在：问要不要先走「新领域」

## 交互原则

- **一次推进一步，问完等用户回答。** 不要一上来就给出完整的 12 周路线，没问清目标的路线大多会作废
- 计划是用户的，AI 补充的判断在计划里标〔AI〕。整节都由 AI 起草的（地图、资料）在小节标题上标一次，用户改过的行不用再标
- 推荐的书、课程、数据源，写进计划前先搜索核实确实存在，作者和书名都要对。搜索不可用时照常推荐，但在计划里标「未核实」，并告诉用户
- 用中文，句子短

## 新领域

### 第 1 步：定目标

依次问，每次只问一个。用户开口时已经答清的跳过，答了一半的只追问缺的那半：

1. **为什么学**：对照四件「本」看它服务哪一件：获取信息、校准对世界的理解、积累资本和人脉、提高决策能力。一件都对不上，或者只是「感觉该学」，直接指出来，问还学不学
2. **学到什么程度**：引导用户用「能做出什么」来回答。「看懂 X」太模糊，要追问看懂之后能做出什么判断或产出
3. **时间预算**：每周几小时，打算持续多久

得到一句话目标和完成判据，复述给用户确认。

### 第 2 步：画地图

AI 先做功课（搜索公开资料），把整张地图一次给出，再请用户挑要改的地方。地图包括：

- 把领域拆成概念、事实、技能三类，各列 3–8 项，标出哪些对目标是必需的
- 领域的核心问题，内行在争论什么
- 入门资料 2–4 份，每份写清为什么选它、读哪些部分。章节号核实不了时按主题写（「讲 QE 的部分」），不要编章节号
- 先修缺口：结合用户已有的背景判断
- 公认最难的部分

地图给完后问两件事：

- 认不认识这个领域的人
- 哪些部分只需要结论、不需要自己判断。这部分交给 AI 或专家，在地图里划掉

地图控制在一屏内，放不下时先砍非必需项，再砍「内行在争论什么」。用户想继续细化时，提醒画地图只占总时间 10% 左右，剩下的边做边补。

### 第 3 步：选主线项目

提 2–3 个候选，请用户挑一个。候选要满足：

- 有真实产出，做完能拿给别人看或者真正用上
- 难度比用户现在的水平高一截
- 能拆成几个阶段，前几周就能做出第一个小成果

### 第 4 步：写计划，定检查点

1. 和用户确认目录：一律是 `<学习根目录>/[<分组>/]<领域>/学习计划.md`。已有相近分组（如 `投资与金融/`）就建在分组下面，没有就直接建在根目录下
2. 按下面的「计划模板」写 `学习计划.md`
3. 第一个检查点定在 4 周后。问用户要不要在滴答建提醒，同意了再建：

```bash
node ${CLAUDE_PLUGIN_ROOT}/skills/dida-tasks/scripts/aitasks.mjs add "学习检查点：<领域>" --col waiting --tags 学习 --due '<日期> 10:00' --remind --content "计划在 <计划路径>。到期运行 /learn-domain 检查点 <领域>"
```

4. 回复用户：计划路径、第一次学习做什么、检查点日期

## 学一次

1. 读计划，找到上次学到哪、卡在哪。`next_checkpoint` 已过期时，先问要不要改做检查点
2. **先检索**：出 2–4 道题，到期的复习卡优先占名额，不够再从最近两三次的学习记录里补；到期卡超过 4 张的，剩下的留到下次，请用户不看资料作答。只给提示，不给答案；用户答完再对照、指出缺漏。第一次学习没有可检索的内容，跳过这步
3. **先解决卡点**：上次「卡在哪」没解决的，检索完先攻它。同一个卡点出现 2 次及以上，单独拎出来练，练熟再往下
4. 用户学新内容时，AI 解释术语、回答追问，但先让用户自己试着回答「为什么」
5. 请用户用自己的话把今天的核心讲一遍，AI 追问漏洞
6. 把今天的内容接到主线项目上：下一步具体做什么
7. **拿反馈**：领域里有可验证的预测（市场、经济数据、比赛结果之类），且最近有新信息（一次会议、一份数据）时，请用户写一条带依据、到期日和判定口径（比如收盘价）的预测进「预测记录」。到期的旧预测由 AI 查实际值，查不到请用户提供，再和用户一起分析对错原因
8. 事实类内容整理成几张问答卡，写进「复习卡」。复习过的卡，答对就把下次复习的间隔翻倍（1 → 2 → 4 → 8 天……），答错回到 1 天
9. 在「学习记录」追加一行，「用时」写分钟数，「检索」一栏写 `答对 x/y` 或 `未检索`

用户想跳过检索直接学新的，可以，但在记录里写「未检索」。连续三次跳过时，提醒一次。

## 检查点

1. 读计划和学习记录
2. 按 `method.md` 第 5 步的三个问题，逐个问用户：
   - 在哪个阶段：新手、胜任还是熟练
   - 投入和收获还成比例吗：比较最近和最早的学习记录
   - 目标还对吗
3. 进步变慢时，提出具体的换输入方案：找什么人聊、读哪份原始资料、看哪个相邻领域
4. 用户决定停止时，尊重，在计划里写明原因，`status` 改成 `已停`
5. 把结论写进计划的「检查点」一节，更新地图和主线项目，把 `next_checkpoint` 改到 4 周后
6. 下一个检查点同样问要不要建提醒；旧提醒用 `aitasks.mjs done "学习检查点：<领域>"` 标完成，领域名用计划标题里的全名

用户不到 4 周就要求检查点，照做，不用劝阻。

## 常见错误

| 错误 | 怎么做才对 |
|---|---|
| 用户一开口就给完整路线 | 先走第 1 步，问清为什么学、学到什么程度 |
| 推荐凭印象写的书 | 搜索核实后再写 |
| 学一次时直接讲新内容 | 先出检索题 |
| 替用户回答检索题 | 只给提示 |
| 只在对话里给计划 | 写进 `学习计划.md`，下次才接得上 |
| 用户没同意就建滴答提醒 | 先问 |
