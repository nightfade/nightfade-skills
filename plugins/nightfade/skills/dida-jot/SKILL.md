# dida-jot：随手记

用户的想法往往是随手打的：句子不完整、语序乱、中英混杂、有错别字。这个 skill 负责把它整理成读得懂的笔记，存进滴答「📒随手记」，同时在末尾保留原文，方便以后对照。

脚本：`${CLAUDE_PLUGIN_ROOT}/skills/dida-jot/scripts/jot.mjs`，下面用 `jot` 代指 `node ${CLAUDE_PLUGIN_ROOT}/skills/dida-jot/scripts/jot.mjs`。清单 ID 在同目录的 `config.local.json`（不进仓库，格式见 `config.example.json`）。复用本机 dida CLI 的登录态；报未登录时让用户在终端运行 `! dida auth login`。

## 命令

| 场景 | 命令 |
|---|---|
| 新建笔记 | `jot add --title 标题 --content 正文 --cat 分类` |
| 看现有分类 | `jot cats`，列出每个分类的笔记数和最近几条标题 |
| 换分类 | `jot move <ID或标题片段> <分类>` |
| 最近的笔记 | `jot list [n]`，默认 10 条 |
| 看一条 | `jot show <ID或标题片段>` |
| 修改 | `jot edit <ID或标题片段> [--title ..] [--content ..]` |
| 删除 | `jot delete <ID或标题片段>`，只删误建的 |

## 整理规则

**只修表达，不改意思。**

可以做：

- 补全残缺的句子，理顺语序，改错别字和语病
- 一段话里有几个意思时拆成几行或几个 bullet
- 口语里的重复、「然后」「就是」这类填充词删掉
- 中英混杂保持原样，专有名词和英文术语不翻译

不要做：

- 不加用户没说的观点、理由、例子、结论或建议
- 不替用户下判断，不把「也许」「可能」改成肯定语气，也不反过来
- 不扩写，整理后的长度和原文差不多；原文本来清楚的就基本照抄
- 意思真的有歧义、补全会猜错时，先问用户一句，不要猜

标题：用一句短话概括这条笔记说的事，不超过 20 个字，用用户自己的词。

## 分类

分类就是「📒随手记」里的分组，只在这个清单里有效。不用标签，标签是全局的，会混进别的清单。

1. 写入前先 `jot cats` 看现有分类
2. 现有分类能比较好地装下这条笔记，就用它，名字一字不差
3. 都不合适才新建。新分类用 2–6 个字的名词，范围要能再装下同类的笔记，比如「育儿」「工作方法」「投资想法」，不要细到只适合这一条
4. 不建意思接近的重复分类；拿不准时宁可归进相近的现有分类
5. 新建了分类，在回复里说一句「新建了分类：xx」

- 传给 `--cat` 的名字不存在时脚本会自动新建
- 接口不能删分组。名称带「可删」的空分组会被下一个新分类改名复用；用户想删分组要在 App 里删

## 正文格式

```
<整理后的正文>

---
**原文**

> <用户原文，一字不改，多行就每行都加 >>
```

原文必须完整、逐字保留，包括错别字和标点。

**整理稿和原文差别不大时，只存整理稿，不附原文**，避免冗余。判断标准：只改了标点、空格、错别字或个别词序，意思和句子基本没变，就算差别不大（批量处理时可以用去掉标点空格后的相似度 ≥ 85% 判断）。补全了残缺句子、拆了段落、删了较多口语填充词的，保留原文。

## 流程

1. 按上面的规则整理，拟好标题
2. `jot cats` 选定或新起分类
3. 直接 `jot add` 写入，不需要先给用户确认
4. 回复用户：标题、分类和整理后的正文。不加评论，不展开讨论这个想法

用户之后说「改一下」时，用 `jot edit` 改正文或标题，原文部分（如有）保持不变。

一次给了几个互不相关的想法时，分成几条笔记分别记。

## 接口限速

滴答开放接口每分钟最多 100 次请求，超了返回 429 `rate_limit_exceeded`，和条目总数无关。脚本遇到 429 会等 60 秒自动重试，最多 3 次。

- 一次操作要调好几次接口（新建并归类约 4 次），批量处理时每条之间停 3–4 秒
- 批量导入要记录已完成的条目，中断后从断点继续，不要整批重跑，否则会产生重复

## 边界

- 只写「📒随手记」这一个清单。这是用户为本 skill 单独开放的写权限；其他清单的规则见 `dida-tasks` skill 的「边界」，除了 AI Tasks 和随手记都只读
- 要做的事、要跟进的事，不进随手记，提醒用户用 dida-tasks 记进 AI Tasks
